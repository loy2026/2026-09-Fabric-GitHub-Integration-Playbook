0.1Revision history#

This playbook is a generalized derivative of an implementation-specific document. All organization names, personal names, repository URLs, workspace names and screenshots containing identifying information have been removed. Technical content has been re-verified against current vendor documentation and extended where the platform has changed.

0.2Ownership and review cadence#

Review this document whenever the platform changes a behaviour it depends on — in practice, at least quarterly. Fabric Git integration changes frequently, and several capabilities described here were in preview at the time of writing.

0.3Placeholder conventions#

Values in angle brackets are placeholders. They are deliberately abstract so that this playbook can be adopted by any organization. Resolve them once, record the decisions in the adoption decision log (Appendix G), and apply them consistently — inconsistent naming is the most common source of confusion in a multi-workspace Fabric estate.

Localize

Before this document is issued

Resolve every placeholder, then delete this callout and the Status line on the cover page. Until that is done, the document describes a pattern rather than your environment.

0.4What this playbook does not cover#

  • Deployment pipelines in depth. Stage configuration, deployment rules and promotion approvals are release-management concerns and belong in a companion document. This playbook stops where main is updated and the release path begins.
  • Capacity sizing and cost management. Branch workspaces consume capacity; that trade-off is acknowledged here but not modelled.
  • Azure DevOps as the Git provider. Several behaviours differ materially — most importantly, service principal authentication for the Git connection is documented for Azure DevOps and not for GitHub, and the commit size limits differ. Where the difference matters it is flagged, but the guidance is written for GitHub.
  • Data modelling, warehouse design and performance tuning. Out of scope.
