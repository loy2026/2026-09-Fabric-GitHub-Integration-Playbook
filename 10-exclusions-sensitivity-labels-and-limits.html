10Exclusions, sensitivity labels and limits

What the integration does not cover is as much a design input as what it does. An unsupported item is protected by none of the controls in this playbook, and its absence from the repository is silent.

10.1Unsupported items and exclusions#

The following are not part of the repository synchronization. Some are item types; others are categories of configuration that live only in the Fabric service.

10.2Sensitivity labels and data protection#

Items carrying sensitivity labels are not supported by default, and their export may be disabled — which means they cannot be committed. An administrator can enable the tenant setting that permits export of labelled items to Git repositories, with the label removed.

This is a data-protection decision rather than a tooling one, and it should be made by whoever owns information protection, not by whoever is configuring source control. The question to answer is whether the repository is an appropriate location for the content the label was applied to protect. The repository typically has a different access list from the workspace, is readable by everyone with repository Read, and retains history indefinitely.

Localize

Decide this explicitly, and record who decided

Either labelled items are excluded from source control — accepting that they are unversioned — or export is enabled and the repository is brought within the scope of the relevant data-protection controls. Both are defensible. Leaving it undecided means the behaviour is determined by a tenant default.

Rule

Git integration is not a backup

It versions definitions. It does not version data. A workspace restored entirely from Git is a functional shell with no rows in it. Data protection requires its own strategy, and that strategy is out of scope here — but its absence is not.

10.3Behaviour when unsupported items are present#

A workspace or Git directory containing unsupported items can still be connected. The unsupported items are ignored: not saved, not synchronized, and not deleted. They appear in the source control pane with the Unsupported status and cannot be committed or updated. This is benign, but it means the repository is not a complete description of the workspace, and anyone reasoning about completeness needs to know that.
