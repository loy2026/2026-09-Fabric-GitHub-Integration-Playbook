22Strategic recommendations

A summary of the judgements embedded in this playbook, separated from the procedures, so they can be argued with directly.

22.1The unified view#

The framework as a whole is a single gated flow:

  • Foundation. The tenant and repository are configured and connected. A two-tier authentication model is established: developers hold fine-grained personal access tokens for interactive work; automation uses a service principal whose credentials are environment-scoped.
  • Development. A developer creates a short-lived feature branch and branches out to an isolated workspace. Data sources resolve through a Variable Library, so the isolation is real.
  • Integration. A pull request carries the change back to main. It is the point at which quality is determined: peer review by the reviewers team, plus whatever automated checks exist, enforced by a ruleset rather than by convention.
  • Release. main updates the Development workspaces, and deployment pipelines promote through protected environments to production.

Every production change is therefore versioned, peer-reviewed, scanned, traceable to a person and a discussion, and reversible. That combination is the deliverable — not the tooling.
